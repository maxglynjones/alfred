# Engineering choices and remaining limits

The aim is an assistant that performs useful tasks and returns the display to passive, while preserving normal Even software. Source paths below describe the current solution; historical experiments are evidence of trade-offs, not shipped features.

| Goal | Constraint / approach tried | Current solution | Remaining limit / evidence |
| --- | --- | --- | --- |
| Independent universal installation | Direct server URLs differ; CORS adjustments cannot change packaged network permissions | Exact-origin configuration/manifest and per-user build, scoped pairing token | No approved runtime-origin mechanism; source distribution is public, universal store onboarding unresolved. `scripts/configure-deployment.mjs`, `src/backend.ts`, `web.py` |
| Timely iPhone reminders without another native app | Glasses WebView is foreground-only; Home Screen Web Push proved cumbersome for the owner | Durable HA reminder records and selected HA Companion notification service | Immediate/scheduled delivery confirmed by user. Cannot read all iOS alerts or promise background G2 display. `__init__.py` |
| Fast everyday requests | Model/tool rounds and local STT can dominate latency; optional tiny-model routing added complexity | Rules/common local operations first, optional bounded interpreter, validated current targets; conversational fallback where allowed | Zero conversation-model call does not mean zero cloud STT. Local is not always faster on 8 GB. `commands.py`, `local_ops.py`, `providers.py` |
| Rich, legible dashboard | Sequential BLE images, partial rendering and opaque bitmap/text overlap; text-only approach traded away visual richness | Four composed image tiles, cached pixels, serial/coalesced bridge writes; native reply layout kept separate | No atomic bitmap commit; real first-render latency still unmeasured in release reference. `dashboard-art.ts`, `smooth-display.ts`, `reply-layout.ts` |
| Quiet, predictable display | Missed WebView timers, busy labels and decorative frames could remain visible | Wall-clock expiry, bounded motion, blank/passive state, changed-content filtering and lifecycle handling | Battery-life equivalence to stock is not measured; foreground suspension/resume still needs device checks. `conversation.ts`, `accent.ts`, `main.ts` |
| Trustworthy action ticks | A model saying done or service acceptance does not prove requested state | Capability-aware current HA discovery, readback, idempotent retry, mutation journals and explicit uncertainty | HA state is not physical optical proof; native scripts/scenes and external sends have weaker receipts. `home.py`, `delivery.py`, `assistant.py` |
| Pair once, recover calmly | Ephemeral WebView origins can lose browser-only state | Native preference storage with ordered writes, browser migration and actionable recovery | Host storage failures still possible; no universal persistence guarantee. `storage.ts`, `main.ts` |
| R1 device info | Stock app data is not necessarily forwarded to the public bridge | Strict identified battery normalization, explicit ring fields and manual identity recovery | No confirmed reading for every host version; no supported SDK health retrieval. Never copy G2 battery to R1. `devices.ts` |
| Natural spoken calls | Local/cloud call experiments did not meet the owner's latency/voice expectations | Calling removed from current product; deliberate G2 capture and readable responses remain | No phone-call experience, British synthetic voice guarantee or CallKit implementation |
| OS-level activation without firmware changes | Installed third-party plugins were absent from tested custom-long-press picker; recovery for speculative firmware was not established | Stock Menu on R1 long press, Alfred first, one tap to launch | User-confirmed middle ground; third-party wake-word/launch integration remains a platform request, not a firmware capability |

The rich dashboard is an intentional choice for occasional glances. Native text is better suited to quick answers. There is no useful single 'FPS' figure for these distinct surfaces. [Measurement methodology](TECHNICAL-REFERENCE.md) separates CPU work, API/STT latency and actual BLE display completion.

Firmware may enable deeper access in other projects, but Alfred does not require a device-level modification. Its SDK/HA approach reduces installation and maintenance scope and coexists with the normal app. We do not claim competing firmware projects are unsafe, nor that SDK limitations can all be removed without vendor support.

Home Assistant provides entities, Areas, service calls, existing vendor integrations, to-do entities, scripts/automations, a persistent host and the iOS notification service. This avoids replicating every vendor protocol or building another native phone client. Google/Microsoft/search still use Alfred adapters. Every adapter, action and provider has an explicit scope; an LLM is not a permission system. MCP is optional, not the sole implementation.
