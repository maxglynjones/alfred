# Release checklist

- Build/test from a clean clone on supported Node/Python versions; run `pnpm check:public` and inspect staged files/history/commit identity.
- Keep generated HA frontend, credentials, logs and owner-origin artifacts ignored. Confirm root/default JSON matches packaged JSON.
- Verify every documented capability is shipped; mark untested provider/cloud paths accurately. Remove calling/firmware/research fragments from the source distribution.
- Check Quick Start → configuration modal → return navigation, keyboard dismissal, reduced motion and narrow iPhone layouts.
- Verify escaped HTML/plain emails, embedded logo, provider acceptance/error handling and real inbox rendering on connected accounts. Sending acceptance is not recipient delivery proof.
- Hardware-test fresh pairing/storage recovery, offline feedback, gestures/exit, text clipping/fade, rich dashboard transfer and battery availability.
- Test one read and one disposable write per enabled home/list/mail/calendar/reminder feature. Confirm actual service state; do not blindly rerun uncertain sends.
- Match Even manifest permissions/origins, SDK/app floor, packaged version, exit/lifecycle handling and no release dependence on a dev URL.
- Supply real public privacy/support/terms URLs and contact fields before Even public submission. Do not substitute a private HA admin URL.
- Solve reviewer access and exact-origin self-hosted distribution before promoting an owner-only build to a universal public listing.
- Retain rollback code and encrypted HA backup outside the public repo; test update and restore on your actual environment.

CI and static checks do not establish Even admission, optical lighting state, universal hardware compatibility, iOS notification delivery or a complete security audit.
